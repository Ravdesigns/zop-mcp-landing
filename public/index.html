Advice from your bill, not a template

FAQ

Questions we get a lot.

Does connecting require an agent or code changes? +

No. The server is remote and speaks streamable HTTP, so connecting registers a URL and a bearer token with your client. Nothing is installed on a developer machine, nothing runs in your cluster, and there is no agent to keep patched.

Can an assistant stop my instances? +

Not on a new token. Reads are the default and writes are granted deliberately, per organisation and per service, by an admin. Until that happens the server can answer questions about your infrastructure and change nothing about it.

Does it bypass our access controls? +

No. Every call goes through the same gateway your dashboard uses, and the gateway decides what the token may do. A token never exceeds the access of whoever issued it, so an assistant cannot reach something its owner could not reach directly.

Does it work across all three products? +

Yes. It is one server and one listing, not one per product. The same token reaches zopnight, zopday and zopcloud, scoped to the services you choose when you issue it.

Which clients are supported? +

Claude Code, Cursor and Codex ship a setup guide. Windsurf and Antigravity are documented. Because it is a remote MCP server rather than a local binary, any client that speaks MCP over HTTP can connect.

Is any of our data used for training? +

No. The server reads your accounts to answer a question and returns the answer. Nothing is copied into a model and nothing is retained for training.

What happens when a token is revoked? +

It stops working immediately. Tokens are issued and revoked in Developer Settings and carry an expiry, so an unused connection closes itself rather than lingering.
